# P1 第一次实跑：AI 生成的侧视角色进切件骨骼

日期：2026-10-21　输入：ImageGen 生成的 1 张侧视基准图 + 4 张部件图（同角色、同画布、平涂透明底）。
产物：`out/rig/`（骨骼 JSON / atlas / 5 个动作 / preview.html / Chrome 截图）。

## 结果

官方 `spine-core` 4.2 校验通过，浏览器里也能播：

```
bones 12, slots 10, regions 6
setup   bounds x=-105 y=-4 w=203 h=714
idle 2.00s / walk 1.00s / run 0.60s / jump 1.20s / wave 1.60s    全部 0 MISSING
```

`walk_sheet.png` 里六帧步态正确：两腿交替、远侧压暗、脚不离地、头随躯干起伏。
**这套流程确实能把一张 AI 角色图变成可动的 Spine 骨骼**，这是 P1 要验证的核心。

## 怎么做的（四步）

```sh
# 1) 生成（人工，ImageGen）
#    1 张侧视全身基准图 + 4 张部件：头/裙/手臂/腿，均侧视、平涂、透明底

# 2) 清理 + 测量：褪棋盘格、去水印与地平线、统计主色 bbox
python measure.py          # → measurements.json + art/clean/*.png

# 3) 把部件标定到模板骨架比例，直接产出 part_00..05
python compose.py          # → out/parts/ + rig-constants.json + out/exploded.png

# 4) 用打过 4 处补丁的 rig 脚本绑骨、打包、校验
python -I ws-rig/spine-cutout-rig.py out/parts out/rig
mv out/rig/kurumi.json out/rig/mint.json
python -I ws-rig/spine-pack.py out/rig --name mint
node ../p0/ws/scripts/spine-verify.mjs out/rig mint
```

`ws-rig/spine-cutout-rig.patch` 就是那 4 处改动的 diff，全部是「新角色必须重算」的量：

| 改动 | 原值 | 新值 | 为什么 |
|---|---|---|---|
| `KNEE_Y` | 50 | 186 | 膝在这张腿图的 y=186（腿图从大腿中段画起） |
| `THIGH_LEN` | 180 | 178 | 胯到膝 = 脚底跨度的 44.4%（参考图实测 328/738） |
| `P["leg-upper"/"leg-lower"]` x | 30 | 70 | 靴子向前伸很长，腿轴线不在 64px 画布中心 |
| `NECK` | (56,10) | (56,40) | 领口在 body 图 y≈37，头骨放 10 会断颈 |
| `SH_NEAR/SH_FAR` | (68,48)/(58,46) | (62,44)/(52,42) | 手臂对到袖窿 |

其余（`ELBOW_Y=150`、`WAIST`、`HIP`、`GROUND`）**沿用模板**——因为 `compose.py` 是把美术套到这些目标跨度上的：
头 126px、裙 357px、臂 275px、腿 401px，都按模板的骨架长度换算。

## 三个只有真跑才会遇到的坑

### 1. ImageGen 的「透明背景」是画上去的棋盘格

`background: transparent` 出来的 PNG，alpha 全是 255，棋盘是像素画上去的（247/225 两级灰）。
直接按 alpha 切图会把整个画布当成不透明 → `measure.py` 里必须先用「灰且亮」判据挖掉，
再按连通块去噪。同一批图右下角还有 `AI生成` 水印，也要按区域清掉。

### 2. 每张部件图都会被重新缩放，必须重新配准

要求了「同画布、同尺寸」，模型仍然各自放大到填满画布（头部图放大到 576×719，手臂 182×1195）。
所以不能靠像素坐标拼装，只能**按特征跨度归一**：每种部件有自己的缩放系数
（head 0.175 / body 0.388 / arm 0.234 / leg 0.323），再把关节对到枢轴上。

### 3. 分部件生成会跑偏，必须盯视角

连衣裙第一版出来是**正面视角**（还带两只袖子），侧视 rig 直接作废。
第二轮加了「这是 profile view，只看得见一侧肩膀和一只袖子、裙摆前后很窄」才画对。
结论：分部件生成时，每个部件的 prompt 都要重申视角，不能只靠参考图。

## 现在的缺陷（都在这张图上）

- **领口/肩部有一条缝**：裙子是按「没有手臂」生成的，袖窿和领口边缘不完整，
  手臂再贴上去就露出一道缺口。人工补 5 分钟能修（补画袖窿内侧），这也是作者强调的
  「部件必须包含被遮挡区域」——AI 分件做不到这一步。
- **上臂被裙子盖住**：裙子的轮廓比手臂宽，视觉上手臂只剩前臂和手。换 `--debug-skin` 能看出来
  骨架是对的，是图层本身的问题。
- **没有裙摆物理**：没加 `--skirt`。这张裙子的下摆是实体，加裙子网格要先把裙摆从 body 里切出来，
  属于下一步。
- **裙子偏长**：美术本身到膝，所以小腿以下才露腿。模板角色是短裙，步态看起来会不一样。

## 结论

| 问题 | 答案 |
|---|---|
| AI 图能不能进这套管线 | 能，但必须重算枢轴（4 个量） |
| 能不能全自动 | 不能。分件、配准、补遮挡区都要人来判断 |
| 现在这套能不能用 | 作为练手/占位可以；做正式角色要修肩颈，最好手绘部件 |
| 下一步 | 修肩颈 → 加 `--skirt` → 接 `pose-to-rig` 试视频动作 |
